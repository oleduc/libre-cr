# Test and integration review — libre-cr v2

## Summary

`cargo test --workspace` reports **169 Rust tests passing** in 0.8s (24 cli unit + 3 cli integration + 32 code-daemon unit + 5 code-daemon mcp_stdio + 5 common unit + 80 review-daemon unit + 1 export_flow + 5 http_api + 6 phase6_search_and_session + 3 spawned_daemon + 3 verbs_api + 2 ws_smoke), and **46 Vitest tests across 13 files** pass in ~2s for the extension. CI runs `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace --all-features`, plus `pnpm typecheck` and `pnpm test` on three OSes for Rust and Linux for the extension.

Confidence is reasonable for unit-level correctness (parsers, validators, store rows, severity ordering, verb selection enforcement) but **thin at the integration seams that matter most for v2**: WS lifecycle (cancel/disconnect/reconnect), real-LLM provider behavior, the wrapper CLI's actual commands, and the full presentation round-trip (`presentation_call` → extension handler → `presentation_result` → agent consumption). The `MockCodeDaemonClient` is also a notable fidelity gap, exposing 4 tools vs the real daemon's 19 with mismatched schemas.

## Critical gaps (block v2)

1. **WS mid-stream cancellation** — `crates/libre-cr-review/src/agent/loop_.rs:332` defines `persist_cancelled` and marks it `#[allow(dead_code)]`. `handle_ws` in `src/server/ws.rs:206-211` selects on `tokio::spawn(reader_task)` finishing and only returns `Error::Internal("client disconnected")` without persisting the partial turn; no test verifies this path or that `persist_cancelled` ever fires. Without coverage, a reviewer who closes the panel loses any in-flight context and the DB row never gets a `cancelled` marker. *Minimum sketch:* open WS, send init, read first `text_delta`, drop the socket, then `GET /v1/sessions/:id` and assert the latest turn has `status == "cancelled"` with the partial answer.
2. **`SpawnedClient` actor restart path** — `crates/libre-cr-review/src/code_daemon/client.rs:297-440` has rich reconnect logic (budget, backoff, `mark_disconnected`, `fail_pending`). The only existing tests are the three `unwrap_mcp_content_*` parse helpers. `tests/spawned_daemon.rs` exercises the happy-path against a real binary but never kills it mid-call. If `restart_on_failure` regresses, the daemon will hang indefinitely on the first child crash with no test catching it. *Minimum sketch:* spawn the binary, issue one `read_file`, send `SIGKILL` to the child via PID, then issue another call and assert either `CodeDaemonUnavailable` (no restart) or eventual success with `health().restart_count == 1` (restart).
3. **Real-LLM provider HTTP behavior** — `AnthropicProvider` and `OpenAICompatProvider` only have unit tests on the SSE event parser and request body shape. Nothing verifies that a 429 / 5xx / disconnect / malformed SSE chunk surfaces correctly as a `ServerFrame::Error` to the WS client. A regression in retry/streaming semantics would ship undetected. *Minimum sketch:* mockito server that returns `429` once then a normal SSE stream; assert one `error` frame is observable or that the agent surfaces a clean error.
4. **`MockCodeDaemonClient` fidelity drift** — `crates/libre-cr-review/src/tools/code_daemon.rs:22-115` returns only `grep`, `read_file`, `find_references`, `git_log` while the real daemon (`crates/libre-cr-code/tests/mcp_stdio.rs:76-95`) exposes 19 tools. The mock's `grep` schema uses `query`; the real one uses `pattern` (`crates/libre-cr-review/tests/spawned_daemon.rs:196`). Every integration test that runs against the mock can't detect a wire-shape mismatch on the verbs that route through tools the mock doesn't list (`compare_to_base`, `show_history`, `related_tests` all imply `git_blame`/`git_show`/`git_diff`). *Minimum fix:* drive the mock from the same `ToolSchema` set the real daemon advertises, or add a per-verb test against the spawned daemon.

## Important gaps

1. **Single-flight 409 race** — `tests/ws_smoke.rs::ws_second_connect_returns_409` uses `tokio::time::sleep(80ms)` between socket-1 send and socket-2 attempt (line 114). Slow CI machines may race here; under load, the busy slot may not be inserted in time and the test would flap. Replace with a poll loop bounded by, say, `tokio::time::timeout(2s)` against an observable signal, or expose `busy_sessions.len()` for direct inspection.
2. **`worktree.rs::pending_action == "clone_required"` flow end-to-end** — covered by the unit tests inside `worktree.rs` but never by the HTTP integration; `tests/http_api.rs::sessions_crud_with_token` relies on `mock.code_intel = true` which short-circuits the prep entirely (route `routes.rs:141`). No test asserts that a real `CloneRequired` state surfaces through `GET /v1/sessions/:id`.
3. **Reader-side presentation result delivery** — `server/ws.rs:174-194` deserializes `ClientFrame::PresentationResult` and pushes into `PendingCalls`. The unit tests in `tools/presentation.rs` cover the dispatcher, and `daemon-ws.test.ts::sends presentation_result` covers the client side, but no integration test joins them: there is no test that drives the agent to emit a `presentation_call`, sends back a `presentation_result` over the WS, and asserts the next agent turn consumes it.
4. **Wrapper CLI command handlers** — `commands/{start,stop,restart,status,doctor,pair,logs,version,update}.rs` are uncovered. At minimum, `status` and `doctor` should be exercised against a running fake-endpoint to confirm they print the expected JSON shapes.
5. **`pr_diff_changed` semantics across sessions vs. same session** — `phase6_search_and_session.rs::create_session_flags_pr_diff_changed_on_new_sha` only covers same-PR-different-sha. Cross-session and missing-sha edges are uncovered.
6. **Origin enforcement on WS upgrade** — `http_api.rs::origin_check_when_configured` covers `POST /v1/sessions` but not the WS upgrade path; nothing prevents a regression where the WS handler skips origin check.
7. **Encryption-at-rest round-trip via the store** — `storage/crypto.rs` has 3 unit tests on the primitive, but no integration test opens an on-disk DB, writes a turn, re-opens with the same `InstallKey`, and reads it back to assert the encrypted column actually decrypts.

## Suggestions (nice to have)

- Add a smoke test that boots `libre-cr-review` from `cargo run` with `--mock-provider` and runs through the full v2 demo path (POST session → WS happy two-round → POST note → POST export → assert markdown). This is the only thing that catches "the binaries link cleanly together."
- Per-OS coverage of `cli/proc.rs::is_alive` on Windows (`#[cfg(unix)]` gates exist; the matching Windows path is untested).
- A negative test for `unwrap_mcp_content` where the child returns `isError: true`.
- Property/fuzz on `parse_anthropic_event` and `parse_openai_event` — handcrafted strings won't catch a malformed delta.
- Extension: a `vitest` test that mounts `ContentApp` against a fake `chrome.storage` + fake daemon endpoint and verifies the pairing → first ask flow.

## Test quality findings

- **`ws_smoke.rs::ws_second_connect_returns_409`** uses `tokio::time::sleep(80ms)` as a synchronization barrier (line 114). This is the only sleep-as-sync in the Rust test suite and is genuinely race-prone on slow CI.
- **All WS-consuming integration tests** (`ws_smoke.rs`, `verbs_api.rs`, `phase6_search_and_session.rs::ws_free_form_ask_streams_when_verb_is_absent`) read frames in an unbounded `while let Some(msg) = ws.next().await { ... }` loop with no `tokio::time::timeout` wrapper. If the server ever stops emitting `Done`, the test hangs indefinitely instead of failing.
- **`tools/router.rs` ScriptedClient test double** and **`worktree.rs` ScriptedClient** are two parallel hand-rolled scripted code-daemon mocks (`tools/router.rs:237`, `worktree.rs:280`). They should share an `internal::ScriptedCodeDaemon` fixture; today a bug in one is invisible to the other.
- **`spawned_daemon.rs` builds the binary lazily via a static `Once`** (lines 22-54) and prints "skipping" if the build fails. That's pragmatic for local iteration but means a broken `libre-cr-code` build can silently degrade these three tests to no-ops in CI — they'll log "skipping" but the overall suite passes. Worth verifying CI logs surface that.
- **`code_daemon/client.rs::unwrap_mcp_content_*`** asserts only the happy parse and the unwrapped-already cases. The "text part isn't JSON" path returns the original wrapper untouched, which is questionable: agents will then see `{content:[{type:"text","plain text"}]}` and likely fail downstream. The test bakes in this behavior without flagging it.
- **`http_api.rs::sessions_crud_with_token`** asserts `worktree_ready == true` but only because `cfg.mock.code_intel = true` in the harness. The real worktree-readiness path is exercised by unit tests in `worktree.rs`, not by integration. The comment on line 46 admits this; the test is correct but the gap is real.
- **`extension/tests/presentation-handlers.test.ts`** suppresses the jsdom "window.open not implemented" warning by relying on jsdom defaults, but the test "open_link accepts https + relative paths" logs `Not implemented: Window's open() method` to stderr. That's a warning not a failure, but it means `openLink` returns `ok: true` without actually verifying a navigation happened — a regression that calls `window.open` with the wrong target would not be caught.
- **`code_daemon/client.rs` actor** uses a `(&mut tokio::spawn(...))` await on line 208-210 of `ws.rs` — `tokio::select!` waits on a freshly-spawned task that simply joins the reader. The structure is hard to read and the reader_task itself can finish naturally on `WsMessage::Close(_)` even when the agent is still running, racing with the agent future. No test verifies the ordering.

## Confirmed good

- **`tests/common/mod.rs` harness** is exemplary: a single `start_server_with_*` function takes any `Arc<dyn Provider>` and yields an `Arc<PairingStore>` so origin/pair tests can mutate state cleanly. The in-process server on `127.0.0.1:0` with returned `SocketAddr` is the right shape.
- **`MockProvider` burst semantics** (`provider/mock.rs:43-73`) — consuming up to and including the next terminator per `stream()` call is exactly what the agent's multi-round loop needs; the second-burst test (`second_burst_after_tool`) demonstrates it correctly.
- **`spawned_daemon.rs::fixture_repo`** builds a real git repo via `git` CLI with controlled committer env. The lazy-build via `Once` + `BUILT_OK` is a clean pattern for keeping a slow integration test optional.
- **`PendingCalls::cancel_all`** is called in `server/ws.rs:196` and unit-tested via `tools/presentation.rs::dispatch_times_out` — one of the only fault paths actually exercised top to bottom.
- **`storage/store.rs` tests** are dense and behavior-focused (`fts_search_finds_note`, `head_sha_persists_and_returns_prev`, `note_with_source_turn_id_stored`) — exactly the right altitude.
- **`cli/tests/integration.rs::TempHome`** correctly snapshots and restores `$HOME` and the `XDG_*_HOME` vars via `Drop`, and uses a `Mutex<()>` to serialize env-mutating tests. Best-practice pattern for env-coupled integration suites.
